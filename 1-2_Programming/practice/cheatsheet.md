## 0. Java-платформа и команды

### JDK, JRE и JVM

- **JVM** (*Java Virtual Machine*) исполняет байт-код Java.
- **JRE** включает JVM и стандартную библиотеку Java API.
- **JDK** включает JRE и инструменты разработки, в том числе `javac`, `java` и `jar`.

Обычный путь программы: `App.java` → `javac` → `App.class` (байт-код) → JVM → выполнение. Поэтому один и тот же `.class` запускается на разных ОС, если там есть подходящая JVM.

### Компиляция и запуск

```powershell
# Находясь в папке с App.java
javac App.java      # создаст App.class
java App            # указывать расширение .class не нужно

# Однофайловый режим: компилирует и запускает без сохранения .class
java App.java
```

Класс с модификатором `public` должен находиться в одноимённом файле: `public class App` — в `App.java`.

### JAR-архив

```powershell
jar -c -f app.jar -e App *.class
java -jar app.jar
```

`jar` упаковывает классы в архив. Опция `-e App` записывает точку входа `App` в манифест архива.

## 1. Структура программы и вывод

```java
public class App {
    public static void main(String[] args) {
        System.out.println("Привет, мир!");
    }
}
```

`main` — точка входа. В классической записи он должен быть `public static`, возвращать `void` и принимать `String[] args`.

- `// комментарий` — до конца строки.
- `/* комментарий */` — многострочный.
- `/** комментарий */` — документационный Javadoc.
- `System.out.print()` выводит без переноса, `println()` — с переносом строки.

## 2. Типы данных, литералы и переменные

Java имеет статическую и строгую систему типов: тип переменной известен компилятору, а несовместимое значение не присвоить без явного преобразования.

### Примитивные типы

| Тип       |  Размер | Пример           | Назначение                      |
| --------- | ------: | ---------------- | ------------------------------- |
| `byte`    |   8 бит | `127`            | Маленькие целые: от -128 до 127 |
| `short`   |  16 бит | `32_767`         | Целые среднего диапазона        |
| `int`     | 32 бита | `2_147_483_647`  | Основной целочисленный тип      |
| `long`    | 64 бита | `8_100_000_000L` | Большие целые, суффикс `L`      |
| `float`   | 32 бита | `3.14F`          | Дробное число, суффикс `F`      |
| `double`  | 64 бита | `3.14159`        | Основной тип для дробей         |
| `char`    |  16 бит | `'A'`            | Одна UTF-16 кодовая единица     |
| `boolean` |       — | `true`           | Логическое значение             |

### Ссылочные типы

Ссылочная переменная хранит ссылку на объект. К ним относятся классы, `String`, массивы, интерфейсы, перечисления и записи.

```java
String course = "Программирование";
int[] scores = {78, 91, 64};
```

### Литералы

```java
int decimal = 1_999_000;   // _ улучшает читаемость
int octal = 017;           // восьмеричный
int hexadecimal = 0xF4E0;  // шестнадцатеричный
int binary = 0b0101_1011;  // двоичный
long population = 8_100_000_000L;
float temperature = 22.5F;
char tab = '\t';
String text = "Java\u2122";
```

Текстовый блок для многострочной строки доступен в Java 15+:

```java
String message = """
        Первая строка
        Вторая строка
        """;
```

### Именование и константы

- Переменные и методы: `camelCase`, например `averageScore`.
- Классы: `PascalCase`, например `StudentReport`.
- Константы: `UPPER_SNAKE_CASE`, например `HOURS_PER_DAY`.
- `final` запрещает присваивать переменной новое значение.

```java
final int HOURS_PER_DAY = 8;
int workHours = HOURS_PER_DAY * 5;
```

## 3. Преобразования и выражения

### Преобразование примитивов

Расширяющее преобразование проходит автоматически, так как диапазон результата шире. Для сужающего нужно явное приведение — часть данных может потеряться.

```java
int value = 511;
long safe = value;            // int -> long
byte overflow = (byte) value; // int -> byte, результат -1
```

В арифметических выражениях `byte`, `short` и `char` сначала становятся `int`.

```java
byte left = 2;
byte right = 3;
byte total = (byte) (left + right);
```

### Операторы

| Группа             | Операторы                         |
| ------------------ | --------------------------------- |
| Арифметика         | `+`, `-`, `*`, `/`, `%`           |
| Присваивание       | `=`, `+=`, `-=`, `*=`, `/=`, `%=` |
| Сравнение          | `<`, `>`, `<=`, `>=`, `==`, `!=`  |
| Логика             | `!`, `&&`, `                      |                           | ` |
| Инкремент          | `++`, `--`                        |
| Побитовые и сдвиги | `~`, `&`, `                       | `, `^`, `<<`, `>>`, `>>>` |

Скобки меняют приоритет и делают код понятнее.

```java
int x = 5;
int after = x++; // after = 5, x = 6
int before = ++x; // x = 7, before = 7
```

### Особенности арифметики

```java
int whole = 15 / 4;        // 3: целочисленное деление
double fraction = 15 / 4.0; // 3.75
int remainder = 15 % 4;    // 3
```

Целочисленное переполнение не вызывает исключение:

```java
int wrapped = Integer.MAX_VALUE + 1; // Integer.MIN_VALUE
```

У `float` и `double` есть особые значения:

```java
double infinity = 1.0 / 0.0; // Infinity
double nan = 0.0 / 0.0;      // NaN
```

## 4. Math, строки и форматирование

`Math` доступен без `import`, потому что находится в `java.lang`.

```java
double area = Math.PI * Math.pow(2.5, 2);
double root = Math.sqrt(16);
int rounded = (int) Math.round(4.6);
double limited = Math.max(0, Math.min(100, 105));
```

Оператор `+` склеивает строку с любым значением. После появления строки всё справа также преобразуется в строку.

```java
System.out.println("Сумма: " + 5 + 10);     // Сумма: 510
System.out.println("Сумма: " + (5 + 10));   // Сумма: 15
```

`printf` даёт форматированный вывод:

```java
int id = 42;
double score = 3.14159;
System.out.printf("id = %04d, score = %.2f%n", id, score);
```

- `%d` — целое число;
- `%f` — дробное число;
- `%s` — строка;
- `%b` — логическое значение;
- `%n` — перенос строки, независимый от ОС.

## 5. Ветвления

### if, else и тернарный оператор

Условие в Java всегда имеет тип `boolean`. Используйте блоки `{}` даже для одной инструкции: так код легче менять и в нём сложнее ошибиться.

```java
int sign;
if (value < 0) {
    sign = -1;
} else if (value > 0) {
    sign = 1;
} else {
    sign = 0;
}

int relu = value < 0 ? 0 : value;
```

Тернарный оператор удобен, когда обе ветки вычисляют значение для одной переменной. Для сложной логики лучше обычный `if`.

### switch

Современный `switch` со стрелками не проваливается в следующий `case`, поэтому `break` не нужен.

```java
int days = switch (month) {
    case 2 -> leapYear ? 29 : 28;
    case 4, 6, 9, 11 -> 30;
    case 1, 3, 5, 7, 8, 10, 12 -> 31;
    default -> 0;
};
```

Если ветке нужно несколько инструкций, используйте блок и `yield`:

```java
String result = switch (score) {
    case 0 -> "нет баллов";
    default -> {
        int rounded = score / 10 * 10;
        yield "около " + rounded;
    }
};
```

### Короткое замыкание

`&&` и `||` вычисляют правую часть только когда это необходимо. Одиночные `&` и `|` вычисляют оба операнда.

```java
if (divisor != 0 && value / divisor > 1) {
    System.out.println("Деление безопасно");
}
```

## 6. Массивы и циклы

### Массивы и Arrays

Массив имеет фиксированную длину (`length`), хранит элементы одного типа и относится к ссылочным типам.

```java
int[] scores = {78, 91, 64};
scores[1] = 100;
int length = scores.length;

int[] sameArray = scores;                    // копируется ссылка
int[] copy = Arrays.copyOf(scores, scores.length); // создаётся новый массив
boolean equal = Arrays.equals(scores, copy);  // сравнение элементов
```

`int[][]` — массив массивов. Его строки могут иметь разную длину:

```java
int[][] groups = {{72, 91}, {48}, {88, 30, 76}};
System.out.println(groups[2][1]); // 30
```

Обращение к `null` даёт `NullPointerException`, а индекс за пределами `0..length - 1` — `ArrayIndexOutOfBoundsException`.

### Циклы

```java
int sum = 0;
for (int score : scores) { // перебор значений
    sum += score;
}

for (int index = 0; index < scores.length; index++) {
    System.out.println(scores[index]);
}

while (condition) {
    // может не выполниться ни разу
}

do {
    // выполнится хотя бы один раз
} while (condition);
```

`continue` переходит к следующей итерации, `break` завершает ближайший цикл.

```java
for (int score : scores) {
    if (score == 0) continue;
    if (score >= 90) break;
}
```

## 7. Строки и методы

### String

`String` неизменяем: операция вроде `text += "!"` создаёт новую строку. Содержимое строк сравнивают через `equals`, а `==` проверяет, одна ли это ссылка.

```java
String first = "Java";
String second = new String("Java");

System.out.println(first == second);        // false
System.out.println(first.equals(second));   // true
```

Не создавайте строку через `new String(...)` без особой причины. При большом числе склеиваний в цикле используйте `StringBuilder`.

### Методы, varargs и перегрузка

```java
static int sum(int left, int right) {
    return left + right;
}

static double sum(double left, double right) { // перегрузка: другая сигнатура
    return left + right;
}

static void greet(String... names) { // varargs внутри является String[]
    for (String name : names) {
        System.out.println("Привет, " + name);
    }
}
```

Аргументы всегда передаются **по значению**. Для примитива копируется само значение. Для массива или другого объекта копируется ссылка, поэтому метод может менять сам объект, но не переменную-ссылку вызывающего кода.

```java
static void increase(int value) { value++; }
static void increaseFirst(int[] values) { values[0]++; }
```

`var` разрешён только для локальной переменной с немедленной инициализацией. Компилятор всё равно выводит конкретный статический тип.

```java
var scores = new int[] {78, 91, 64};
var title = "Баллы";
```

## 8. Основы ООП

### Классы, объекты и ссылки

Класс описывает состояние объекта через поля и поведение через методы. Объект создаётся оператором `new`; переменная ссылочного типа хранит ссылку на него.

```java
Rectangle first = new Rectangle(3, 4);
Rectangle sameObject = first;
sameObject.setWidth(10);

System.out.println(first.getWidth()); // 10: обе ссылки указывают на один объект
```

`null` означает, что ссылка не указывает ни на какой объект. Вызов метода через `null` вызывает `NullPointerException`.

### Поля, методы и static

Поля экземпляра принадлежат конкретному объекту. `static`-поле или метод принадлежит классу и существует в одном экземпляре на весь класс.

```java
class Student {
    private static int nextId = 1;
    private final int id = nextId++;
}

System.out.println(Math.PI); // статическая константа класса Math
```

В нестатическом методе `this` обозначает текущий объект. У статического метода объекта нет, поэтому обратиться к полям экземпляра из него нельзя.

### Инкапсуляция и конструкторы

Делайте поля `private`, а доступ к ним предоставляйте через методы. Так класс контролирует корректность своего состояния.

```java
class Rectangle {
    private double width;
    private double height;

    Rectangle(double width, double height) {
        setSides(width, height);
    }

    void setSides(double width, double height) {
        if (width <= 0 || height <= 0) {
            throw new IllegalArgumentException("Стороны должны быть положительными");
        }
        this.width = width;
        this.height = height;
    }

    double area() {
        return width * height;
    }
}
```

Конструктор имеет имя класса и не имеет возвращаемого типа. `this(...)` вызывает другой конструктор того же класса и должен быть первой инструкцией в конструкторе.

| Модификатор      | Доступ                               |
| ---------------- | ------------------------------------ |
| `private`        | Только внутри класса                 |
| без модификатора | Внутри пакета                        |
| `protected`      | Внутри пакета и наследникам          |
| `public`         | Всем классам, которым доступен пакет |

### Композиция и неизменяемость

Композиция означает, что объект хранит другой объект как поле: у `Circle` есть `Point center`. Она выражает отношение «имеет» и часто лучше наследования для объединения сущностей.

Неизменяемый объект после создания нельзя изменить. Обычно для него нужны: класс без расширения, `private final` поля, отсутствие сеттеров и неизменяемые вложенные объекты.

```java
final class Point {
    private final double x;
    private final double y;

    Point(double x, double y) {
        this.x = x;
        this.y = y;
    }
}
```

`final` у ссылки запрещает заменить ссылку, но не делает объект по ссылке неизменяемым.

### Пакеты и import

Пакет создаёт пространство имён и обычно соответствует структуре папок.

```java
package ru.itmo.practice;

import java.util.Arrays;
import static java.lang.Math.PI;
```

В файле сначала идёт `package`, затем `import`, затем объявления классов. В одном `.java`-файле может быть один `public` класс, а имя файла должно совпадать с именем этого класса.
## 9. Наследование и специальные классы

### extends, super и @Override

Наследник получает доступные поля и методы родителя: `class Square extends Rectangle`.

- `super(...)` вызывает конструктор родителя и должен стоять первой строкой конструктора.
- `super.method()` вызывает версию метода из родительского класса.
- `@Override` ставят над переопределённым методом: компилятор проверит, что сигнатура совпадает.
- Перегрузка — одно имя, разные параметры. Переопределение — та же сигнатура в наследнике.

`private`-члены не наследуются напрямую. `protected` доступен классу, его наследникам и классам того же пакета.

### Приведение типов

Ссылку на наследника можно сохранить в переменную родительского типа — это upcasting:

```java
Shape shape = new Square(4);
```

При вызове переопределённого обычного метода сработает реализация объекта (`Square`), а не тип ссылки (`Shape`). Обратное преобразование делают только после проверки:

```java
if (shape instanceof Square square) {
    System.out.println(square.area());
}
```

### Object: toString, equals и hashCode

Все классы неявно наследуются от `Object`.

- `toString()` возвращает понятное строковое представление объекта.
- `equals(Object)` сравнивает объекты по смыслу.
- Если `equals` переопределён, нужно переопределить и `hashCode`: равные объекты обязаны иметь одинаковый хеш-код.

Для сравнения строк, обёрток и объектов обычно используют `equals`, а `==` оставляют для примитивов и проверки той же ссылки.

### final, enum и record

- `final` у переменной запрещает переназначение, у метода — переопределение, у класса — наследование.
- `enum` задаёт ограниченный набор именованных значений; у него могут быть поля, конструктор и методы.
- `record Point(int x, int y)` — компактный неизменяемый класс-данные. Компилятор создаёт поля, конструктор, аксессоры `x()`/`y()`, `equals`, `hashCode` и `toString`.

### StringBuilder, обёртки и точные числа

`String` неизменяем: при множественных склейках в цикле удобнее `StringBuilder`.

```java
StringBuilder text = new StringBuilder("Java");
text.append(" ").append(25);
```

Обёртки (`Integer`, `Double`, `Boolean`) позволяют хранить примитивы в коллекциях и имеют `null`, но сравнивать их через `==` ненадёжно. Автоупаковка превращает `int` в `Integer` автоматически.

`BigInteger` используют для очень больших целых чисел, `BigDecimal` — для точных десятичных расчётов. Для `BigDecimal` строковый конструктор избегает погрешности `double`:

```java
BigDecimal price = new BigDecimal("19.90");
```
## 10. Полиморфизм, интерфейсы и стандартная библиотека

### Полиморфизм и абстрактные классы

Полиморфизм подтипов позволяет хранить объекты наследников в переменной или массиве типа предка и вызывать переопределённые методы без проверки каждого конкретного класса.

```java
Shape[] shapes = {new Circle(2), new Rectangle(4, 3)};
for (Shape shape : shapes) {
    System.out.println(shape.area());
}
```

`abstract class` описывает общую, но неполную сущность. Такой класс нельзя создать через `new`, но он может быть типом ссылки, содержать поля, конструкторы и обычные методы. Наследник обязан реализовать все унаследованные абстрактные методы или тоже быть `abstract`.

### Интерфейсы

Интерфейс задаёт контракт поведения. Класс наследует только один класс через `extends`, но может реализовать несколько интерфейсов через `implements`.

```java
class Duck implements Flyable, Swimmable, Walkable {
    @Override
    public void fly() { }

    @Override
    public void swim() { }
}
```

Методы интерфейса без реализации неявно `public abstract`; поля — `public static final`. Также существуют `default`, `static` и `private` методы. Интерфейс выбирают для общего поведения несвязанных классов, абстрактный класс — когда нужны общие состояние или базовая реализация.

### Comparable и Comparator

`Comparable<T>` задаёт естественный порядок объекта через `compareTo`. `Comparator<T>` — внешний, альтернативный порядок через `compare`.

```java
Arrays.sort(tasks);                         // Comparable
Arrays.sort(tasks, new PriorityComparator()); // Comparator
```

Результат сравнения: отрицательный — первый объект меньше, ноль — равен, положительный — больше. Для безопасного сравнения чисел удобно `Integer.compare(a, b)`.

### Вложенные классы

- `static class` не связан с экземпляром внешнего класса и видит только его `static`-члены.
- Inner class создаётся через `outer.new Inner()` и имеет доступ к полям конкретного `outer`.
- Local class объявляют внутри метода; он виден только в этом методе.
- Anonymous class создают и реализуют в одном выражении, обычно для одноразовой реализации интерфейса или класса.

### ArrayList и List.of

`ArrayList<T>` — изменяемый динамический массив ссылочных значений. Основные операции: `add`, `get`, `set`, `remove`, `size`. Вставка или удаление в середине сдвигает элементы.

`List.of(...)` создаёт неизменяемый список. Для редактирования создают копию:

```java
List<Integer> fixed = List.of(1, 2, 3);
ArrayList<Integer> mutable = new ArrayList<>(fixed);
```

### Scanner

`Scanner` читает токены из `System.in`, строки или файла. Перед `nextInt()` полезно проверить `hasNextInt()`, а ресурс закрывают через try-with-resources.

```java
try (Scanner scanner = new Scanner(System.in)) {
    while (scanner.hasNextInt()) {
        System.out.println(scanner.nextInt());
    }
}
```

После `nextInt()` перед `nextLine()` часто остаётся символ перевода строки; его нужно отдельно считать `nextLine()`.

### Дата и время

Пакет `java.time` содержит неизменяемые классы: `LocalDate`, `LocalTime`, `LocalDateTime`, `ZonedDateTime`. Методы `plus...` и `minus...` возвращают новый объект.

- `Period` измеряет разницу дат в годах, месяцах и днях.
- `Duration` измеряет промежуток времени в секундах и наносекундах.
- `ZoneId` и `ZonedDateTime` нужны, когда важен часовой пояс.

### Регулярные выражения

`Pattern` хранит скомпилированное выражение, `Matcher` проверяет и ищет совпадения.

```java
Pattern pattern = Pattern.compile("(\\w+)@(\\w+\\.)+\\w{2,}");
Matcher matcher = pattern.matcher("student@se.itmo.ru");
boolean isEmail = matcher.matches();
```

Частые элементы: `\d` — цифра, `\w` — буква/цифра/`_`, `\s` — пробельный символ, `.` — любой символ; `*`, `+`, `?`, `{n,m}` задают количество. Скобки создают группы захвата, доступные через `group(n)`.
## 11. Исключения и чистый код

### Иерархия исключений

Все ошибки времени выполнения происходят от `Throwable`.

- `Error` — серьёзные проблемы JVM; обычно их не обрабатывают.
- `Exception` — ситуации, которые программа может обработать.
- Checked-исключения — наследники `Exception`, кроме `RuntimeException`; их нужно поймать или объявить в `throws`.
- Unchecked-исключения — `RuntimeException` и его наследники: например, `NullPointerException`, `IllegalArgumentException`, `ArithmeticException`.

### try, catch, finally, throw и throws

```java
try {
    readConfig();
} catch (IOException exception) {
    System.out.println(exception.getMessage());
} finally {
    System.out.println("Выполнится всегда");
}
```

- `throw` создаёт и выбрасывает исключение.
- `throws` объявляет, что метод может передать checked-исключение вызывающему коду.
- `catch` идут от более конкретного типа к более общему.
- Multi-catch объединяет обработку: `catch (IOException | SQLException exception)`.
- `try-with-resources` автоматически закрывает объекты `AutoCloseable`:

```java
try (Scanner scanner = new Scanner(System.in)) {
    // работа со scanner
}
```

### Собственные исключения

Своё исключение моделирует ошибку предметной области. Для обязательной обработки наследуют `Exception`, для программной ошибки — `RuntimeException`.

```java
throw new VeggyBreakException(
        "Репа разломилась",
        new IllegalStateException("strength = 0")
);
```

Второй аргумент — исходная причина; её можно получить через `getCause()`. Не стоит глушить ошибки пустым `catch` или объявлять `throws Exception` без необходимости.

### Проектирование и чистый код

- **DRY**: не дублируй логику; вынеси повторение в метод или класс.
- **KISS**: выбирай простое решение, если сложность не нужна.
- **YAGNI**: не добавляй функциональность «на будущее».
- **SOLID**: одна ответственность, расширение без переписывания стабильного кода, корректная подстановка наследников, маленькие интерфейсы, зависимость от абстракций.
- **GRASP**: назначай ответственность классу, у которого есть нужные данные; поддерживай низкую связанность и высокую связность внутри класса.

Чистый код использует точные имена, короткие методы с одной задачей, константы вместо магических чисел и единый формат. Комментарий нужен для причины или ограничения, а не для пересказа очевидной строки кода. По возможности не возвращай и не передавай `null`.

Композиция (`has-a`) обычно гибче наследования (`is-a`): объект делегирует работу своему полю, а не жёстко зависит от предка. Закон Деметры советует не обходить длинные цепочки объектов вроде `order.getCustomer().getAddress().getCity()`.

### ИИ как помощник

ИИ может объяснить ошибку, предложить черновой код, помочь с тестами и документацией. Но сгенерированный результат нужно прочитать, собрать и проверить самостоятельно; не передавай в запросы секреты, персональные данные и код, который нельзя раскрывать. За решение и академическую честность отвечает разработчик.

### Частые ловушки Java

- Для отрицательных чисел нечётность: `value % 2 != 0`, а не `== 1`.
- `double` неточен для денежных расчётов: используй `BigDecimal` и строковый конструктор.
- В `50_000 * 50_000` переполнение происходит до присваивания в `long`; начни с `50_000L`.
- `01234` — восьмеричный литерал. `char + char` даёт `int`.
- В `x *= 3 / 2` сначала вычисляется `3 / 2`, то есть `1`.
- Сравнение обёрток через `==` проверяет ссылки и зависит от кэша; используй `equals`.
- `BigInteger` и `BigDecimal` неизменяемы: результат `add`/`subtract` нужно присвоить.
- `Math.abs(Integer.MIN_VALUE)` остаётся отрицательным: положительное значение не помещается в `int`.
- При смешении конкатенации и тернарного оператора ставь скобки: `"x = " + (value != null ? value : "нет")`.
## 12. Модули и инструменты разработки

### Пакеты, classpath и JAR

Пакет группирует классы и создаёт пространство имён. Его имя пишут в первой строке файла и сопоставляют с каталогом:

```java
package itmo.practice.app;
```

Обычно используют перевёрнутое доменное имя в нижнем регистре. `import` позволяет обращаться к классу коротким именем; `import static` импортирует статические члены. `java.lang` импортируется автоматически. Импорт пакета не включает его подпакеты.

Classpath — список каталогов и JAR-файлов, где компилятор и JVM ищут классы. Его задают флагом `-cp` / `-classpath`. JAR — ZIP-архив с классами и ресурсами; `META-INF/MANIFEST.MF` может содержать `Main-Class` для запуска через `java -jar`.

### JPMS-модули

Модуль Java 9+ объединяет пакеты и явно описывает зависимости в `module-info.java`:

```java
module itmo.practice {
    requires java.logging;
    exports itmo.practice.app;
}
```

- `requires` — модуль-зависимость.
- `exports` — открывает пакет для использования другими модулями.
- `opens` — открывает пакет для рефлексии.
- `requires transitive` передаёт зависимость потребителям модуля; `requires static` нужна только во время компиляции.

На classpath классы входят в безымянный модуль. На module-path JAR без `module-info.java` становится автоматическим модулем. Для модульного примера:

```powershell
javac -d bin src/module-info.java src/itmo/practice/app/*.java
java --module-path bin --module itmo.practice/itmo.practice.app.App
```

### Javadoc

Javadoc начинается с `/**` и генерирует HTML-документацию из исходников. Первое предложение — короткое описание. Для публичных методов полезны `@param`, `@return`, `@throws`; для классов — `@author`, `@version`, `@since`.

```java
/** Возвращает сумму двух чисел. */
public int add(int first, int second) {
    return first + second;
}
```

Документация отвечает на «что?» и «зачем?», а не пересказывает очевидное «как?». Команда генерации: `javadoc -d doc src/itmo/practice/app/*.java`.

### Тестирование, assert и отладка

`assert` проверяет инвариант во время разработки и по умолчанию выключен. Включают флагом `-ea`:

```java
assert amount >= 0 : "Количество не может быть отрицательным";
```

Unit-тест проверяет один небольшой участок кода. Структура AAA: Arrange — подготовка, Act — действие, Assert — проверка. В JUnit 5 используют `@Test`, `assertEquals`, `assertTrue`, `assertThrows` и другие утверждения. Хороший тест — FAST: быстрый, изолированный, повторяемый, самопроверяемый и написанный вовремя.

Отладчик IDE помогает остановиться на breakpoint, выполнить Step Over/Into/Out, посмотреть переменные и задать условную точку останова.

### Логирование

Для диагностики применяют логгер вместо случайных `System.out.println`. В `java.util.logging` логгер создают через `Logger.getLogger(...)`, а сообщения разделяют по уровням: `SEVERE`, `WARNING`, `INFO`, `CONFIG`, `FINE`.

```java
private static final Logger LOGGER = Logger.getLogger(App.class.getName());
LOGGER.info("Расчёт начат");
```

Логгер передаёт сообщение обработчику (`Handler`), фильтр может его отсеять, форматтер оформляет вывод. В проектах также распространены Log4j2 и Logback.

### Git

Базовый цикл: `git status` → `git add <file>` → `git commit -m "сообщение"` → `git push`. Для начала работы: `git init` создаёт репозиторий, `git clone <url>` копирует существующий.

Полезные команды: `git log`, `git branch`, `git switch`, `git merge`, `git pull`. Делай небольшие осмысленные коммиты, используй ветки для отдельных задач, проверяй код перед коммитом и не добавляй в репозиторий секреты, `bin`, `.class` и локальные настройки.
## 13. Типы, generics и коллекции

### Обёртки и Unicode

Примитивы хранят значения, ссылочные типы — ссылки на объекты. Классы-обёртки (`Integer`, `Double`, `Boolean`, `Character`) позволяют использовать примитивные данные там, где нужны объекты: в generic-классах и коллекциях.

```java
Integer boxed = 42; // auto-boxing
int value = boxed;  // auto-unboxing
int year = Integer.parseInt("2026");
```

`char` хранит одну UTF-16 code unit, а не обязательно один символ Unicode. Символы вне BMP, например эмодзи, занимают пару `char`; для них применяют `codePoint` и `Character.toChars`.

### Generic-классы и методы

Generics задают тип как параметр и переносят проверку ошибок на этап компиляции:

```java
Box<String> box = new Box<>();
box.put("Java");
String text = box.get();
```

Типовые параметры обычно называют `T` (тип), `E` (элемент), `K`/`V` (ключ/значение), `N` (число). Generic-метод ставит параметры типа перед возвращаемым типом:

```java
static <T> T getFirst(List<T> values) {
    return values.get(0);
}
```

В Java работает type erasure: в байткоде информация о большинстве параметров типа стирается. Поэтому нельзя создать `new T()`, `new T[10]` или проверить `object instanceof Box<String>`.

### Границы и PECS

Верхняя граница `T extends Number` разрешает использовать методы `Number` для `T`. Wildcard `? extends X` безопасен для чтения `X`, а `? super X` — для добавления `X`.

Правило PECS: **Producer Extends, Consumer Super**.

```java
static <T> void copy(List<? super T> destination, List<? extends T> source) {
    destination.addAll(source);
}
```

`List<Integer>` не является подтипом `List<Number>`: generic-типы инвариантны. Для связи между ними нужны wildcard-ограничения.

### Collections Framework

`java.util` содержит интерфейсы и реализации коллекций. `Collection<E>` — общая основа для `List`, `Set`, `Queue` и `Deque`; `Map<K, V>` стоит отдельно, потому что хранит пары ключ-значение. Все коллекции работают со ссылочными типами, поэтому `int` становится `Integer` автоматически.

Основные операции `Collection`: `add`, `remove`, `contains`, `size`, `isEmpty`, `clear`, `addAll`, `removeAll`, `retainAll`.

### List, Queue, Deque, Set и Map

- `ArrayList` — динамический массив: быстрый доступ по индексу, но вставка в середину сдвигает элементы.
- `LinkedList` — двусвязный список; также реализует `Deque`.
- `Queue` обычно FIFO: `offer`, `poll`, `peek`. `PriorityQueue` возвращает минимальный элемент по естественному порядку или `Comparator`.
- `ArrayDeque` — эффективный стек и двусторонняя очередь: `addFirst`, `addLast`, `pollFirst`, `pollLast`, `push`, `pop`.
- `HashSet` хранит уникальные элементы без порядка; `LinkedHashSet` сохраняет порядок добавления; `TreeSet` сортирует элементы.
- `HashMap` хранит пары ключ-значение без порядка; `LinkedHashMap` помнит порядок вставки; `TreeMap` сортирует по ключу.

`List.of`, `Set.of` и `Map.of` создают неизменяемые коллекции. Для редактирования скопируй их в изменяемую реализацию: `new ArrayList<>(List.of(...))`.

`Collections` содержит алгоритмы для списков: `sort`, `reverse`, `shuffle`, `binarySearch`. `Arrays` делает то же для массивов и даёт `Arrays.asList(...)`: это представление поверх исходного массива с фиксированным размером, поэтому `add` и `remove` в нём недоступны.

### Iterator и вспомогательные алгоритмы

`for-each` работает через `Iterable` и `Iterator`. Если во время обхода нужно удалять элементы, используй `iterator.remove()`, а не изменение коллекции внутри `for-each`.

Класс `Collections` содержит общие алгоритмы для списков: `sort`, `reverse`, `shuffle` и `binarySearch`. Шаблон Command из лабораторной отделяет вызов команды от её выполнения: вызывающий объект хранит `Map<String, Command>`, а конкретные команды реализуют общий интерфейс `Command`.
## 14. Шаблоны проектирования и ввод-вывод

### Iterator, Builder и сортировка

`Iterable<T>` возвращает `Iterator<T>`; `for-each` использует его неявно. Итератор последовательно обходит данные с помощью `hasNext()` и `next()`. Удалять текущий элемент во время обхода можно через `iterator.remove()`.

Builder собирает сложный объект по шагам. Его методы возвращают самого строителя, а `build()` создаёт готовый объект. `Comparable<T>` определяет естественный порядок через `compareTo`, а `Comparator<T>` задаёт внешний порядок через `compare`. Списки сортируют `list.sort(...)`, массивы — `Arrays.sort(...)`.

### Потоки и кодировки

`java.io` работает с потоками: `InputStream`/`OutputStream` для байтов и `Reader`/`Writer` для символов. Байтовые потоки используют для произвольных данных, символьные — для текста. При преобразовании между ними указывай кодировку, обычно `StandardCharsets.UTF_8`.

`read()` возвращает `-1` в конце входного потока. `flush()` передаёт данные из буфера, `close()` освобождает ресурс. Для ресурсов используй try-with-resources:

```java
try (BufferedReader reader = Files.newBufferedReader(path, StandardCharsets.UTF_8)) {
    System.out.println(reader.readLine());
}
```

### Декораторы, данные и сериализация

Потоки-декораторы добавляют возможности другому потоку: `BufferedReader`/`BufferedWriter` добавляют буферизацию, `InputStreamReader`/`OutputStreamWriter` преобразуют байты и символы, `PrintWriter` даёт `print`/`printf`, GZIP-потоки сжимают данные.

`DataInputStream` и `DataOutputStream` записывают примитивы и строки в бинарном виде; читать нужно в том же порядке, в котором записывали. `ObjectOutputStream`/`ObjectInputStream` сериализуют объекты, реализующие `Serializable`. Стандартная сериализация зависит от структуры класса. Поле `transient` не сериализуется; `Externalizable` даёт полный ручной контроль записи, но требует публичного конструктора без аргументов. Для долговременного хранения обычно выбирают JSON, CSV или другой явный формат.

CSV и JSON можно записывать вручную для простых случаев, но специальные символы и вложенные структуры быстро усложняют код. На практике используют библиотеки: Apache Commons CSV или OpenCSV для CSV, Gson или Jackson для JSON.

### Консоль, Random и файлы

Стандартные потоки: `System.in`, `System.out`, `System.err`. `Scanner` разбирает текст на токены; проверяй тип через `hasNextInt()` перед `nextInt()`. `Console` может быть `null` в IDE. `Random` генерирует псевдослучайные значения, а фиксированный seed делает последовательность повторяемой.

Для работы с файлами предпочтительны `Path` и `Files` из `java.nio.file`: `Path.of(...)`, `Files.exists`, `Files.createFile`, `Files.readString`, `Files.writeString`, `Files.copy`, `Files.move`, `Files.deleteIfExists`. `File` — старый класс для путей; NIO.2 поддерживает больше операций и файловых систем.

## 15. NIO, сеть, дата-время и лямбды

### NIO: Buffer и Channel

NIO работает с **буферами** и **каналами**. У буфера есть фиксированная `capacity`, текущая `position`, граница доступных данных `limit` и необязательная `mark`; всегда `0 ≤ mark ≤ position ≤ limit ≤ capacity`.

Обычный цикл: записать через `put` → `flip()` для чтения → прочитать через `get`. `clear()` готовит весь буфер к новой записи, `rewind()` повторяет чтение, а `compact()` сохраняет непрочитанные байты и освобождает место после них. Есть `ByteBuffer`, `CharBuffer`, `IntBuffer` и другие типизированные буферы; порядок байтов задаёт `ByteOrder`. При переводе текста между байтами и символами явно указывай `Charset`, обычно UTF-8.

`Channel` похож на поток, но может быть и читаемым, и записываемым, а данные передаются через `ByteBuffer`. `FileChannel` поддерживает позицию в файле, `transferTo`/`transferFrom`, scatter/gather I/O с массивом буферов и отображение файла в память через `map` (`MappedByteBuffer`). Ресурсы каналов закрывай через try-with-resources.

### Сеть и неблокирующий ввод-вывод

Сеть бывает клиент-серверной или одноранговой. TCP/IP — практический стек протоколов; IP-адрес определяет хост, порт — процесс на нём. `InetAddress` представляет адрес или имя, `InetSocketAddress` объединяет адрес и порт; DNS сопоставляет доменное имя с IP. IPv4 содержит 32 бита, IPv6 — 128.

TCP устанавливает соединение, гарантирует порядок и доставку байтового потока. В классическом API сервер использует `ServerSocket.accept()`, клиент — `Socket`, а обмен идёт через потоки. UDP не устанавливает соединение и передаёт отдельные датаграммы: `DatagramSocket` и `DatagramPacket`; он быстрее и проще, но порядок и доставка не гарантированы.

NIO-аналоги — `SocketChannel`, `ServerSocketChannel` и `DatagramChannel`. В блокирующем режиме `read`, `accept` или `receive` ждут результат. В неблокирующем они сразу возвращают `0` или `null`, если данных пока нет. `Selector` позволяет одному потоку ждать события многих каналов; канал регистрируют с интересами `OP_ACCEPT`, `OP_CONNECT`, `OP_READ`, `OP_WRITE`, а готовность проверяют через `SelectionKey`.

`URI` идентифицирует ресурс, `URL` описывает его местонахождение и может открыть соединение. `URLConnection` позволяет настроить запрос до чтения ответа. Шаблон Proxy предоставляет тот же интерфейс, что и реальный объект, и делегирует ему работу, добавляя, например, кэширование, контроль доступа или логирование; динамический вариант создают через `java.lang.reflect.Proxy` и `InvocationHandler`.

### Дата и время

Старые `Date`, `Calendar` и `TimeZone` изменяемы и неудобны для прикладной логики; `Date` по сути хранит миллисекунды от Unix epoch (1970-01-01T00:00:00Z). Для нового кода выбирай неизменяемый и потокобезопасный `java.time`.

- `Instant` — точный момент на временной шкале.
- `LocalDate`, `LocalTime`, `LocalDateTime` не содержат часового пояса.
- `ZoneId`, `ZoneOffset`, `ZonedDateTime`, `OffsetDateTime` добавляют пояс или смещение.
- `DateTimeFormatter` форматирует и разбирает строки; `Period` измеряет даты, `Duration` — время.

Методы `plus`, `minus`, `with` возвращают новый объект. `TemporalAdjusters` выражают правила вроде «первый понедельник месяца». Между API можно перейти через `Date.from(instant)` и `date.toInstant()`.

### Функциональные интерфейсы и лямбды

Функция высшего порядка принимает или возвращает другую функцию. Рекурсия выражает задачу через саму себя, но расходует стек вызовов; для длинных последовательностей часто безопаснее цикл. Чистая функция не меняет внешнее состояние и для одинаковых аргументов возвращает одинаковый результат.

Функциональный интерфейс имеет ровно один абстрактный метод (default-методы и методы `Object` не считаются); аннотация `@FunctionalInterface` проверяет это правило. Лямбда получает целевой тип такого интерфейса:

```java
Predicate<Student> excellent = student -> student.averageMark() > 4.75;
Consumer<Student> print = System.out::println;
```

Часто применяют `Predicate<T>` для условия, `Consumer<T>` для действия, `Function<T, R>` для преобразования, `Supplier<T>` для получения значения и их `Bi...`/примитивные варианты. Ссылки на методы записывают как `Type::staticMethod`, `object::instanceMethod`, `Type::instanceMethod`, `Type::new`.

Лямбда может захватывать локальные переменные только если они `final` или effectively final. Лямбда вместе с такими захваченными значениями образует замыкание.
## 16. Функциональные интерфейсы, Stream API, JDBC и безопасность

### Функциональные интерфейсы

`java.util.function` содержит типовые формы функций: `Supplier<T>` возвращает `T` без аргументов, `Consumer<T>` принимает `T` и ничего не возвращает, `Predicate<T>` проверяет условие, `Function<T, R>` преобразует `T` в `R`. `UnaryOperator<T>` — `T → T`, `BinaryOperator<T>` — `T, T → T`; варианты `Bi...` принимают два аргумента. Примитивные варианты (`IntPredicate`, `IntFunction` и другие) избегают boxing.

Методы `andThen`, `compose`, `and`, `or`, `negate` помогают составлять функции и условия. `Runnable` и `Comparator<T>` тоже функциональные интерфейсы. Лямбду можно передать туда, где ожидается соответствующий интерфейс.

### Stream API

Stream — одноразовый конвейер, а не коллекция: он не хранит элементы, не изменяет источник и обычно выполняется лениво. Состав: **источник** → ноль или больше **промежуточных операций** → одна **завершающая операция**.

Источники: `collection.stream()`, `Stream.of`, `Arrays.stream`, `IntStream.range`, `Files.lines`. Промежуточные операции возвращают поток: `filter`, `map`, `flatMap`, `distinct`, `sorted`, `limit`, `skip`, `peek`. Завершающие запускают вычисление и закрывают поток: `forEach`, `count`, `min`/`max`, `reduce`, `collect`, `anyMatch`/`allMatch`/`noneMatch`.

```java
Map<String, Double> averages = students.stream()
        .collect(Collectors.groupingBy(Student::group,
                Collectors.averagingDouble(Student::averageMark)));
```

`Optional<T>` выражает возможное отсутствие результата. Вместо небезопасного `get()` используй `orElse`, `orElseGet`, `orElseThrow`, `ifPresent` или `map`. Параллельный stream не делает код автоматически быстрее: он полезен только для независимых, достаточно больших задач без общих изменяемых данных. `BaseStream` задаёт общие методы `parallel`, `sequential` и `close`; `Spliterator` умеет делить обход для параллельной обработки.

### Реляционные БД, SQL и JDBC

Реляционная БД хранит отношения: таблица состоит из столбцов (атрибутов) и строк (кортежей). СУБД создаёт и обслуживает базу. DDL описывает схему (`CREATE`, `ALTER`, `DROP`), DML меняет данные (`INSERT`, `UPDATE`, `DELETE`), а `SELECT` выбирает их. Ограничения `PRIMARY KEY`, `FOREIGN KEY`, `NOT NULL`, `UNIQUE`, `CHECK` защищают целостность; `JOIN` соединяет строки таблиц по связанным полям.

JDBC: `DriverManager` или `DataSource` создаёт `Connection`; затем `PreparedStatement` выполняет параметризованный запрос, `ResultSet` читает строки. `executeQuery()` используют для `SELECT`, `executeUpdate()` — для изменений, `execute()` — для произвольного запроса. Всё закрывай try-with-resources; транзакцию завершают `commit()` либо `rollback()`. `addBatch`/`executeBatch` объединяют однотипные изменения, а `DatabaseMetaData` и `ResultSetMetaData` описывают БД и столбцы результата.

```java
String sql = "SELECT name FROM students WHERE group_name = ?";
try (PreparedStatement statement = connection.prepareStatement(sql)) {
    statement.setString(1, group);
    try (ResultSet result = statement.executeQuery()) {
        while (result.next()) System.out.println(result.getString("name"));
    }
}
```

Не склеивай пользовательские значения со строкой SQL: это открывает SQL-инъекции. Передавай их параметрами `PreparedStatement`. `DataSource` отделяет настройку соединения от кода; пул соединений переиспользует подключения. JNDI позволяет получить зарегистрированный `DataSource` по имени. `RowSet` расширяет идею `ResultSet`: `CachedRowSet` способен хранить данные без постоянного соединения, `WebRowSet` — XML-представление, `FilteredRowSet` — фильтрацию, `JoinRowSet` — соединение результатов.

### Провайдеры и модули

Сервис — известный интерфейс, а провайдер — его реализация. `ServiceLoader<S>` находит ноль, одну или много реализаций во время работы; прикладной код зависит от интерфейса, а не от конкретного класса. Шаблон ServiceLocator централизует получение службы, но `ServiceLoader` — стандартный механизм Java для поиска провайдеров. На classpath поставщика перечисляют в `META-INF/services/<полное.имя.Сервиса>`, а в JPMS — через `provides Service with Implementation`. Потребитель указывает `uses Service`.

В `module-info.java`: `requires` объявляет зависимость, `exports` открывает пакет потребителям, `opens` разрешает глубокую рефлексию. `requires transitive` передаёт зависимость дальше, `requires static` нужна только при компиляции. Classpath использует безымянный модуль; module-path — именованные или автоматические модули. Open module открывает все пакеты для рефлексии, а `jlink` собирает минимальный образ JRE из выбранных модулей.

### Пароли и секреты

Пароли нельзя хранить открытым текстом или как быстрый одиночный хеш (`MD5`, `SHA-1`, `SHA-256`). Для нового кода используют медленные алгоритмы, созданные для паролей: обычно Argon2id; при ограничениях доступны scrypt, bcrypt или PBKDF2. У каждого пароля должна быть уникальная случайная соль. Work factor подбирают на реальном сервере и повышают со временем.

В JDK можно показать принцип через `PBEKeySpec` и `SecretKeyFactory` с `PBKDF2WithHmacSHA256`. Пароль лучше хранить в `char[]`, чтобы затереть после применения, а сравнение хешей выполнять `MessageDigest.isEqual`. Pepper — дополнительный общий секрет, который держат отдельно от БД; он не заменяет соль. Секреты не попадают в исходники и Git: используй секрет-хранилище, защищённую переменную окружения или конфигурацию с ограниченными правами.

## 17. Многопоточность и java.util.concurrent

### Терминология

Слово «поток» в Java означает две разные вещи: **thread** — нить выполнения (параллельная работа) и **stream** — последовательность данных (I/O Stream, Stream API). Многозадачность бывает **кооперативная** (задача сама уступает ресурс) и **вытесняющая** (переключает диспетчер ОС в произвольные моменты). **Процесс** имеет свою память, **поток** работает внутри процесса и разделяет память с другими потоками — отсюда дешёвое переключение контекста и все проблемы с общими данными.

Две модели параллельной обработки: **распараллеливание** (каждая задача проходит все этапы, задачи делятся между обработчиками) и **конвейер** (обработчик выполняет один этап для всех задач).

Реализация потоков в Java: 1.0 — Green Threads (N:1), 1.3+ — Platform (Native) Threads (1:1), 21+ — Virtual Threads (N:M).

### Thread и Runnable

`Runnable` — функциональный интерфейс задачи с методом `run()`. `Thread` — исполнитель: его `start()` создаёт отдельный поток ОС, а прямой вызов `run()` выполнит код в текущем потоке без параллельности.

```java
class Task implements Runnable {
    public void run() { /* тело задачи */ }
}
new Thread(new Task()).start();

// или короче
new Thread(() -> System.out.println("hi")).start();
```

Жизненный цикл: `NEW` → `RUNNABLE` (ready/run) → `BLOCKED` / `WAITING` / `TIMED_WAITING` → `TERMINATED`.

Основные методы: `Thread.currentThread()`, `getName()`/`setName()`, `getPriority()`/`setPriority()`, `getState()`, `isAlive()`, `isDaemon()`/`setDaemon()` (только до `start()`), `sleep(long)`, `join()`, `yield()`.

Прерывание: `interrupt()` устанавливает флаг; `Thread.interrupted()` проверяет и сбрасывает, `isInterrupted()` — не сбрасывает. `sleep`, `join`, `wait` бросают `InterruptedException`. Завершать потоки через `stop()`/`suspend()`/`resume()` нельзя — они deprecated. Демоны (`setDaemon(true)`) завершаются вместе с JVM; shutdown-хуки добавляют через `Runtime.getRuntime().addShutdownHook(...)`.

### Гонки, synchronized, volatile

**Гонка (race condition)** возникает при наличии общих изменяемых данных: хотя бы два потока обращаются к переменной и хотя бы один пишет. `counter++` — не атомарная операция, а три шага: load → add → store. Итог зависит от планировщика, результат недетерминирован.

Решения: убрать общие данные (локальные переменные), сделать объекты неизменяемыми или синхронизировать доступ.

Модификатор `synchronized` защищает критическую секцию через **монитор** объекта (intrinsic lock). Монитор реентерабелен: тот же поток может войти повторно. Три формы: `synchronized`-метод экземпляра (по `this`), `synchronized`-статический метод (по `Class`), `synchronized (obj)`-блок (по любому объекту). `synchronized` гарантирует и видимость, и атомарность.

Модификатор `volatile` даёт **видимость без кэша** и отношение **happens-before** между записью и последующим чтением, но **не даёт атомарности**. В JVM чтение/запись ссылок и примитивов (кроме `long`/`double`) атомарны; JIT может кэшировать значения в регистрах, поэтому без `volatile` цикл `while (!done) i++;` в примере лекции никогда не увидит изменения `done`.

### wait, notify и Condition

Методы `Object` (`wait`, `notify`, `notifyAll`) вызываются только при захваченной блокировке. `wait()` помещает поток в **wait set** объекта и освобождает монитор до сигнала/прерывания/таймаута. Паттерн producer-consumer использует `while` в цикле перед `wait()`, потому что возможны ложные пробуждения.

```java
synchronized void put(int v) throws InterruptedException {
    while (ready) wait();
    value = v; ready = true;
    notifyAll();
}
```

Интерфейс `Lock` — более гибкая замена `synchronized`: `lock()`/`unlock()` можно вызывать в разных методах, есть `tryLock()` и `tryLock(time)`, `lockInterruptibly()`, справедливая очередь. `Condition` — аналог `wait`/`notify`, но с несколькими очередями на один Lock: `await()`, `signal()`, `signalAll()`. Реализация — `ReentrantLock`, `ReadWriteLock`/`ReentrantReadWriteLock` (много читателей, один писатель).

### Executor, ExecutorService, Callable, Future

`Executor` — абстракция исполнителя задач: `void execute(Runnable)`. Отделяет постановку задачи от её запуска — клиент не знает, как именно она выполнится.

`ExecutorService extends Executor` добавляет управление жизненным циклом и результатами: `submit(Callable)` возвращает `Future`, `shutdown()`/`shutdownNow()` останавливают пул, `invokeAll`/`invokeAny` запускают батчи.

`Callable<V>` возвращает значение и может бросить checked-исключение: `V call()`. `Future<V>` — контейнер для будущего результата: `get()` блокирует, `get(timeout)` — с таймаутом, `isDone()`, `cancel()`.

`ScheduledExecutorService` добавляет `schedule`, `scheduleAtFixedRate` (по периоду), `scheduleWithFixedDelay` (пауза после завершения). `CompletableFuture` — композиция асинхронных шагов: `supplyAsync`/`runAsync`, `thenApply`/`thenAccept`/`thenCombine`, `join()`.

### Пулы потоков и ForkJoin

Создание потока дорого, поэтому потоки переиспользуют через **пул**. `ThreadPoolExecutor` настраивается `corePoolSize`, `maximumPoolSize`, `keepAliveTime` и очередью. Логика поступления: `threads < core` — новый поток, `core < threads < max` — в очередь, `threads = max` — очередь или отклонение.

Фабрики `Executors`: `newSingleThreadExecutor`, `newFixedThreadPool(n)`, `newCachedThreadPool` (переиспользует и завершает при простое), `newWorkStealingPool`, `newVirtualThreadPerTaskExecutor`.

`ForkJoinPool` реализует «разделяй и властвуй» и **work stealing**: рекурсивно делим задачу на подзадачи через `fork()`, ждём результаты через `join()`. `RecursiveAction` — без результата, `RecursiveTask<V>` — с результатом. Параллельные стримы изнутри используют `ForkJoinPool.commonPool()`, полезны при известном размере и произвольном доступе (`ArrayList`, массивы).

### Синхронизаторы

- **`Semaphore(permits)`** — управляет числом разрешений: `acquire()`/`release()`. `Semaphore(1)` — бинарный семафор.
- **`CountDownLatch(count)`** — одноразовая защёлка: `countDown()` уменьшает, `await()` ждёт обнуления.
- **`CyclicBarrier(parties, task)`** — многоразовый барьер: последний пришедший выполняет задачу перед открытием, `reset()` сбрасывает.
- **`Phaser(parent, parties)`** — универсальный барьер-защёлка с фазами (`register`, `arrive`, `arriveAndAwaitAdvance`).
- **`Exchanger<V>`** — обмен объектами между двумя потоками через `exchange(V)`.

### Блокирующие очереди и конкурентные коллекции

`BlockingQueue` и `BlockingDeque` дают три вида операций: обычные (`add`/`remove`/`element`), блокирующие (`put`/`take`), с таймаутом (`offer`/`poll(time, unit)`). Реализации: `ArrayBlockingQueue`, `LinkedBlockingQueue`, `LinkedBlockingDeque`, `PriorityBlockingQueue`, `DelayQueue`, `SynchronousQueue` (размер 0). `TransferQueue.transfer(E)` ждёт фактического получения.

Конкурентные коллекции (`java.util.concurrent`) используют оптимизированные алгоритмы вместо общих блокировок:

- **`ConcurrentHashMap`** — сегментированная блокировка, атомарные `putIfAbsent`, `compute`, `computeIfAbsent`, `merge`, `replace`.
- **`ConcurrentSkipListMap`/`Set`** — отсортированные, оптимистичный подход.
- **`ConcurrentLinkedQueue`/`Deque`** — неблокирующие очереди.
- **`CopyOnWriteArrayList`/`Set`** — любая модификация создаёт новую копию, чтение и итераторы работают со старой; хороши для read-mostly.

`Collections.synchronizedXxx` — старый вариант с одной общей блокировкой, плохо масштабируется.

### Атомарные типы и CAS

**Атомарная операция** выполняется без промежуточных состояний. В основе `java.util.concurrent.atomic` — **CAS (Compare-and-Swap)**, аппаратная инструкция `CMPXCHG`:

```java
int cmpxchg(int expected, int updated) {
    int old = value;
    if (old == expected) value = updated;
    return old;
}
```

`AtomicInteger`, `AtomicLong`, `AtomicBoolean`, `AtomicReference`, `AtomicIntegerArray`, `LongAdder`/`DoubleAdder`, `LongAccumulator`/`DoubleAccumulator`. Методы: `incrementAndGet`, `getAndIncrement`, `addAndGet`, `getAndSet`. Классический паттерн частотного анализа:

```java
ConcurrentHashMap<String, LongAdder> freq = new ConcurrentHashMap<>();
for (String key : keys) {
    freq.computeIfAbsent(key, k -> new LongAdder()).increment();
}
```

### Проблемы многопоточности

- **Deadlock** — потоки ждут блокировок друг друга.
- **Livelock** — потоки активны, но не продвигаются.
- **Starvation** — поток не получает ресурс.
- **Недерминированность** — результат зависит от планировщика.

Профилактика: неизменяемые объекты (все поля `private final`, нет сеттеров, копии изменяемых вложений), фиксированный порядок захвата блокировок, таймауты на `tryLock`, аккуратное использование `notifyAll`.
